What the numbers mean

A .pptx is a ZIP archive with a folder structure inside it. Almost everything in that structure is small XML describing where shapes sit and what they say — the kind of data that compresses to almost nothing. The bytes that actually make a file large live in one place, ppt/media/, which holds a separate copy of every picture, sound clip and video the deck uses.

That has a consequence worth stating plainly: the size of a .pptx is almost entirely decided by what you put in it, not by how you saved it. A deck carrying a three-minute 1080p screen recording is large before PowerPoint has done anything wrong, and no amount of saving will change that. The report above exists to tell you which of those situations you are in.

Reading the three totals

  • Whole file is the size on disk — the number Windows or Finder shows you.
  • Media folder is everything under ppt/media/. If this is most of the file, shrinking the deck means shrinking media, and the rest of this page applies.
  • Everything else is slides, layout XML, theme data, embedded objects and archive overhead. This is normally small. When it is not, the cause is nearly always an embedded workbook, an embedded font, or years of accumulated editing history — the non-media table in the report names which.

Percentages are calculated against the whole file, so they are the share of the download each item is responsible for. A single video at 78% is not a subtle problem.

If media is the problem

The report tells you which kind of media dominates, and the fix differs by kind.

Video and audio

Video is the single most common reason a deck becomes unshareable, and it is the hardest to fix after the fact. In PowerPoint for Windows, File → Info → Compress Media re-encodes every clip and offers three quality levels. Choosing 720p rather than the default usually takes a deck from hundreds of megabytes to tens.

PowerPoint for Mac has no equivalent feature, so on a Mac the clip has to be re-encoded before it is inserted — the file you link or embed is the file that ends up in the deck. Compressing video also strips embedded captions and any secondary audio tracks, which is worth knowing before you overwrite your only copy.

Pictures

Pictures are easier. Select any image and use Picture Format → Compress Pictures. Two settings in that dialog do most of the work: untick Apply only to this picture so the setting covers the whole deck, and tick Delete cropped areas of pictures. That second box matters more than it looks — PowerPoint keeps the parts of an image you cropped away, and a deck built from screenshots can lose a third of its size to pixels nobody can see.

The full procedure, including what each quality setting costs you in visible detail, is in how to compress a PowerPoint file.

If media is not the problem

A report showing a small media folder and a large file is unusual, and it narrows the cause to three things.

  • An embedded Excel workbook. Pasting a chart as an Excel object puts a copy of the entire spreadsheet inside the .pptx, including sheets nobody will ever see. Pasting it as a picture, or linking it instead, removes that copy. See embedding an Excel chart for the difference between the two.
  • Embedded fonts. File → Options → Save has a setting that embeds the fonts used in the deck so it renders correctly on machines that lack them. Useful with an unusual typeface, pure overhead with a standard one.
  • Accumulated editing history. A file saved over and over for years carries residue from every one of those saves. Opening it and using File → Save As to write a fresh copy under a new name discards it. This is also the first thing to try on a file that is slow to open rather than merely large.

Doing this without a tool

Everything this page reports can be checked by hand, and it is worth knowing how — it works on a locked-down machine where you cannot run anything, and it is the same trick that makes the tool possible.

  1. Work on a copy. Renaming a .pptx to .zip and back is harmless, but there is no reason to do it to your only copy.
  2. Rename the copy so it ends in .zip. Windows will warn you that changing the extension may make the file unusable. It will not, provided you change it back afterwards.
  3. Open the .zip and look inside ppt/media/. Sort that folder by size. The largest file in it is what is making your deck large.
  4. Rename it back to .pptx when you are done looking. Do not edit anything inside the archive — PowerPoint will refuse to open a file whose internal structure has been altered.

This is also the answer to a related question: if someone sends you a .pptx and you want to know what is in it before opening it, the archive will tell you. Slides are in ppt/slides/, notes in ppt/notesSlides/, and every embedded asset is visible by name in ppt/media/.

Why this runs in the browser

Decks are frequently confidential — a pitch, a handover, an internal review. Uploading one to a stranger's server to find out why it is large is a bad trade, so this tool does not ask you to. There is no upload step because there is no server: the page reads the archive structure directly using JavaScript in your own browser, and the file never crosses the network.

You do not have to take that on trust. Disconnect from the internet and use the tool — it behaves identically, which is not true of a tool that uploads your file and analyses it remotely.

The parsing is deliberately shallow for the same reason. The tool reads the ZIP index and reports the sizes recorded there; it never decompresses the contents, never renders an embedded image, and never executes anything from the file. A corrupt or hostile .pptx can at worst produce a wrong number.

Questions

Is my file uploaded anywhere?
No. JavaScript in your browser reads the file locally and nothing is sent over the network. There is no server side to this tool, so there is nowhere for the file to go. Disconnecting from the internet and using it anyway is the proof.
Why can it report sizes without opening the file in PowerPoint?
Because a .pptx is a ZIP archive, and a ZIP archive keeps an index at the end recording the size of every file it contains. Reading that index is enough to produce accurate numbers. Nothing is decompressed, which is why the result appears instantly even for a file of several hundred megabytes.
Can I check the same thing without a tool?
Yes — copy the file, rename the copy to end in .zip, and open it. The ppt/media/ folder is the answer. See doing this without a tool above for the full procedure, including why you should not edit anything inside the archive.
The report says media is a small part of my file. What else is in there?
An embedded Excel workbook and embedded fonts are the two common causes; a file saved repeatedly over years can also carry editing history. The non-media table lists every part over 1% of the file, which in practice names the cause — a part too small to clear that bar is also too small to be worth chasing. File → Save As under a new name clears the last of the three.
Does it work on .ppt files or .potx templates?
It works on .potx, because a template is built exactly the same way as a .pptx. It does not work on the older .ppt format, which is a binary file rather than an archive — open that in PowerPoint and save it as .pptx first.
